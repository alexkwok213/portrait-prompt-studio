# 人像图片模板库

纯文字生成的人像提示词工具。照片只用来**拆解成提示词模板**，从不作为生成输入。

## 两条起手式，一条生成路

| 你有什么 | 起手 | 规范 |
|---|---|---|
| 一段描述，没照片 | 直接写提示词 | `references/text-to-image.md` |
| 一张照片要学 | 七步反推成模板，再改模板 | `references/photo-reverse-engineering.md` |
| 已有模板 + 替换需求 | 定位元素，只改那一项 | `references/template-workflow.md` |

生成永远只用文字。没有「把原图喂给工具」这条路。

## 反推要做到多详细

七步：通读全图 → **光线定位** → 人物与表情 → 姿态支撑与手 → 服装材质 → 背景景深 → 成像特征。

三个硬要求：

1. **每条结论要写出「怎么看出来的」**，不是只有结论。
2. **每句话对应画面一处**。「柔和的光」不算描述；「她左脸颊更亮，鼻右侧有一小片淡阴影」才算。
3. **观察 / 推测 / 设计三桶分开**，不把推测写成事实。

光线那步最重：主光方向、硬度（附阴影边缘的样子）、色温、**逐个列出的阴影清单**、补光、轮廓光、背景明暗。

详细示范见 `templates/window-curtain-uniform-v1/template.md`——那份是按七步走完的完整反推，中文 1225 字、英文 846 词，每一节都写明了判断依据。

## 照片放哪

`templates/photos/` 集中放，命名 `<slug>__<变体>.png`。**不放模板目录里**——一张原图常同时支撑好几个模板，集中才不会改一处漏一处。

`preview.png` 放在模板目录里，它是**生成产物**（验证模板写对没），不是原图，别拿去当参考照片。

## 年龄要三样齐写（已实测）

**模型会把年龄往小了画。** 只写「九岁」会出六岁的娃娃脸。必须同时给：

1. 年龄数字
2. 身高 / 体态
3. 去掉哪些婴儿肥特征

实测对比：

| 模板写法 | 实出图 |
|---|---|
| 「约九岁」 | 六岁模样——脸极圆、四肢短、婴儿肥重 |
| 「九岁 + 128cm + 比同龄略高 + 四肢比一年前长但仍偏短 + 婴儿肥仍在 + 肩未发育」 | ✅ 九岁感正确 |
| 「十二岁 + 142cm + 四肢拉长 + 婴儿肥消退 + 下颌线初现」 | ✅ 十二三岁，形态正确 |

同样是「九岁」，加不加体态描述结果差一档——**只写数字必翻车**。

完整对照表见 `template-workflow.md` 的「年龄阶段对照表」（覆盖 4–18 岁五个阶段，含身高区间与「显大/显小」写法）。

## 防成人化（13–18 岁必写）

把年龄往上拉之后，模型容易一路拉到**成年脸**。分界不在「有没有婴儿肥」，而在**下颌角的圆润度**。

必写这三句：

| | 中文 | English |
|---|---|---|
| 下颌角 | 下颌线清晰但**下颌角仍是少女的圆润轮廓，没有成年人的棱角** | a clear jawline whose **angle is still rounded rather than angular** |
| 脸型 | 柔和的鹅蛋形，**比小学阶段明显拉长** | a soft oval, **visibly longer than it would be at primary-school age** |
| 残留 | 脸颊**还留有一点点属于少女的圆润** | her cheeks **still keep a little of her girlish roundness** |

缺下颌角那句脸会偏成熟；缺「少女圆润」那句四肢和皮肤也会一起老气。

**各年龄段服装与表情边界**（越界会出违和感）：

| 年龄段 | 服装 | 表情 | 绝对不写 |
|---|---|---|---|
| 7–9 岁 | 校服衬衫+背带裙、或针织衫 | 正在进行的微笑、露齿 | 唇釉、腮红 |
| 10–12 岁 | 校服、运动服、针织开衫 | 微笑、抿嘴浅笑 | 唇色描述、低领 |
| **13–15 岁** | **校服衬衫+针织开衫+百褶裙到膝上** | **还没完全展开的微笑（不露齿）** | **口红、高跟鞋、丝袜、低领、露肩、任何曲线描述** |
| 16–18 岁 | 校服或简洁便装 | 自然表情 | 浓妆、露肩低领 |

初中段表情要点：不宜再写露齿大笑（幼态），也不宜面无表情（呆板），**半成品微笑**最合适。

## 替换模板

```bash
python3 build_templates.py        # 改了 template.md 后重跑，刷新工具数据
open assets/template_browser.html
```

浏览器里选模板 → 填替换需求 → 工具告诉你该改哪几个元素 → 只改那些元素 → 复制提示词。

匹配走两层：字符串层（元素名、可替换值双向包含）+ 语义层（E1–E10 各有关键词词典，能抓「连衣裙→服装」这类换词）。实测 19 条常见改法全部命中。

**E7 光位、E9 画幅机位、E10 成像倾向默认受保护**——它们决定物理关系，改了人物和环境的光会打架。真要改（如换成户外正午）必须连带重建阴影描述。

### 要「换个人」时，改三个元素

用户说「换个脸 / 换套发型 / 换套服装」这类需求，**E2 + E3 + E4 必须同改**——这三者是「像不像同一个人」的最小判别集。只改服装的话脸不变，看起来仍是同一个人。

| 原值 | 换成 |
|---|---|
| 圆脸 + 大眼双眼皮 | 略方柔和椭圆 + **单眼皮** + 低平眉 |
| 空气刘海 + 双马尾 | 齐眉平刘海 + 齐下巴短 bob |
| 白皙均匀无瑕 | 偏黄肤色 + 淡雀斑 + 局部粗糙 |
| 眼神直视好奇 | 看向镜头外 + 安静不设防 |
| 整齐白牙 + 有光泽唇 | 略不整齐牙 + 无光泽唇 |

两个要点：换的元素要**具体到可观测形态**（`a narrower single eyelid fold close to the lash line`），不能笼统写「普通眼睛」；把弱特征**反向**（原来嘴角高 2mm，改成低 2mm），否则只是对称镜像。

**换服装要连带处理手的关系**：原模板写「左手持书、手指弯曲」，换成 oversize 毛衣后袖口会盖住手——必须改成 `the cuffs hang over her wrists, her thumbs tucked into the openings, her hands lost inside the sleeves`，否则会出现「毛衣袖口 + 完整手指」的矛盾。

实测效果见 `output/studio-uniform-v1__swap-ebof.png`。

匹配工具现在三层：字符串层 + 语义词典 + **组合层**（识别「换个脸」这类整体重塑，一次命中 E2+E3+E4）。实测 15 条常见需求全部命中。

## 去水印

本模型（无论怎么写否定词）都会在右下角加「AI生成」标记，已验证无效。后期处理是唯一可靠手段：

```bash
python3 remove_watermark.py 图片.png# 输出 图片-clean.png
```

脚本原理：从被覆盖区域的**上边缘与左边缘**取真实背景像素，沿两方向线性插值重建渐变，四边羽化混合。

**关键坑：不要用单一颜色填。** 影棚背景本身有渐变，填纯色会留下一块明显的方块（我第一次就这么干错了）。必须做渐变重建。

## 区分人物时不能踩的坑

**区分手段要挑「不明显但有效」的维度，不要挑「一出来就毁」的特征。**

反面案例：给 9 岁女孩加雀斑想避开「白净甜妹」家族，用户反馈「脸上好多斑，很不好看」。

| ✅ 好区分（有效又好看） | ❌ 坏区分（有效但难看） |
|---|---|
| 眼皮单/双 | 雀斑、痣、疤 |
| 脸型轮廓 | 皮肤病变、瑕疵 |
| 眉毛高低平直 | 偏黄/灰暗到不健康 |
| 眼神方向（直视↔看向别处） | 龅牙、缺牙 |
| 嘴宽与唇厚 | 极端不对称五官 |
| 发型分缝与长度 | 油腻、脏乱、炸毛 |
| 牙齿整齐度（轻微） | 明显的畸形 |

**判断标准**：这个特征在真实生活里会不会让人觉得「这个人不好看」。雀斑在成人脸上是特色，在 9 岁孩子脸上就是「脏」。**同一特征对不同年龄的观感完全不同。**

想让皮肤干净就写否证：`no spots, no freckles, no moles and no blemishes of any kind`。

**优先用「弱特征反向」做区分**：把嘴角高度反转、让眼神偏离镜头——既能避开重复，又不毁观感。

## 已知限制

- **水印拦不住**。写了 `no watermark, no AI-generated label, no signature, no text overlay` 四项，模型仍会在右下角加「AI生成」。三种写法全试过，无效。只能后期裁切或交付时说明——**不要试第四种否定词写法**。
- **柔光与方向光不可兼得**。写「均匀无阴影」模型就给正面平光，左右差异消失；想保方向光就得允许阴影。二选一，别同时写矛盾的话。
- 暖调光词会污染背景颜色——写了 `warm-toned light`，背景 `warm-beige` 会出成偏深暖橙。背景颜色要独立重申。
- 文字无法保证独特身份或真实感。连续针对性尝试仍重复模板脸时，明说限制。
- 抽象材质词会被误解成具体物件（「斑驳」→ 出花卉装饰图案），必须同时写否证（`no pattern, no floral decoration`）。
- 微弱特征（嘴角轻微不对称）靠形容词不稳定，要用量化差异（`two millimetres higher`）。
- 强度词会盖过质感词（`Strong warm-toned soft light` → 出硬光），光位句要把两者分开写。
- 匹配工具靠关键词词典，说法太偏可能匹配不到，此时手动对照元素表。
- `studio-uniform-v1` 这条路线问题集中（三次出图同样三个毛病），问题已逐条记在该模板的「已知问题」里。
- 现成模板只有两个，都是生成稿反推。要更好的模板就往 `templates/photos/` 放真实照片再反推。
